# نظام إدارة السائقين والمركبات (Frontend)

واجهة أمامية كاملة (React + Vite + Tailwind CSS) لإدارة السائقين والمركبات
وإصدار بطاقات تعريفية للسائقين. المشروع Frontend فقط ويعتمد حاليًا على
LocalStorage، مع تصميم طبقة Services بحيث يسهل استبدالها بـ API حقيقي مستقبلاً.

## التشغيل

```bash
npm install
npm run dev
```

ثم افتح الرابط الذي يظهر في الطرفية (عادة `http://localhost:5173`).

## حساب المدير الافتراضي

| الدور | اسم المستخدم | كلمة المرور |
| ----- | ------------ | ----------- |
| مدير  | admin        | admin123    |

لا توجد حسابات موظفين افتراضية: يُنشئ المدير الموظفين من صفحة **الموظفون**
(كلمة المرور الافتراضية للموظف الجديد `123456` ويمكن تغييرها).

## أهم مسار للتجربة

1. سجّل الدخول كمدير (admin / admin123) ثم من "الموظفون" أضف موظفًا جديدًا
2. سجّل الخروج ثم الدخول بحساب الموظف الذي أنشأته
3. من الشريط الجانبي اختر "إضافة سائق"
4. أدخل بيانات السائق، ارفع صورته، اختر نوع المركبة، وأدخل بياناتها
5. لاحظ تحديث معاينة البطاقة مباشرة أثناء الكتابة
6. اضغط "إنشاء البطاقة" لتوليد رقم بطاقة تلقائي وحفظ البيانات
7. من صفحة تفاصيل البطاقة اضغط "طباعة البطاقة" لمعاينة الطباعة (بحجم بطاقة هوية حقيقي 85.6×54 مم)
8. سجّل الدخول كمدير لمشاهدة جميع البطاقات من كل الموظفين، وإيقاف البطاقات أو إعادة تفعيلها، والتقارير، والإعدادات

## ملاحظات تقنية

- **التخزين:** البيانات محفوظة في LocalStorage (حدّه نحو 5MB). تُصغَّر الصور وتُضغط تلقائيًا
  عند رفعها، وتعرض صفحة الإعدادات نسبة المساحة المستخدمة. عند امتلاء المساحة تظهر رسالة
  واضحة بدل فقدان البيانات بصمت.
- **الإعدادات:** عدد أيام "قريب الانتهاء" ومدة الصلاحية ولون البطاقة والشعار تؤثر مباشرة
  على حالات البطاقات والمعاينة، وتظهر معاينة حيّة للبطاقة في صفحة الإعدادات.
- **الأداء:** الصفحات تُحمَّل عند الحاجة (Code Splitting)، ومكتبة الرسوم البيانية لا تُحمَّل
  إلا في صفحة التقارير.

## هيكلة المشروع

```
src/
  components/   مكونات مشتركة (Button, Input, Modal...) وأخرى خاصة بالبطاقات والسائقين والمركبات
  pages/        صفحات admin و employee
  services/     طبقة الوصول للبيانات (LocalStorage الآن، API لاحقًا)
  context/      Providers: AuthContext و ToastContext و SettingsContext
  hooks/        useAuth و useToast و useSettings و useAsyncData و usePageTitle
  utils/        دوال مساعدة (تنسيق التاريخ، حالة البطاقة، رقم البطاقة، التحقق)
  data/         بيانات وهمية (Mock Users) وبيانات أولية تجريبية
  routes/       AppRoutes وحراس المسارات (ProtectedRoute, AdminRoute, EmployeeRoute)
```

## ربط Backend مستقبلاً

كل الدوال في مجلد services/ معزولة عن الـ Components تمامًا. عند توفر API حقيقي
يكفي تعديل محتوى ملفات services/*.js (مثلاً استبدال storage.read بـ axios.get)
دون الحاجة لتعديل أي صفحة أو مكوّن.
